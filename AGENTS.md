# Costly — working rules

Costly is a single-user personal finance web application, built as a Bachelor diploma project
between October 2026 and June 2027. It records a person's money and turns their own history into
analysis, forecasts and quantified, goal-aware decisions.

## Architecture constraints

Decided. Changing any of these needs a new ADR and explicit approval.

- **One NestJS modular monolith**, two runtime roles — API and worker — sharing the same modules
  and database (ADR-0001).
- **Module dependencies point one way only**:
  `identity → ledger → recurring → import → planning → analytics → forecasting → simulation → insights`,
  plus shared `platform`. Each module owns its tables and is reached through one public facade.
  Cross-module "data changed" goes through the recompute marker and a job, never an upward call.
- **Money is integer minor units** in `bigint`, always positive, direction from the transaction
  type. No floats, no `numeric` in application code (ADR-0002).
- **Prisma for persistence and migrations, parameterised raw SQL for analytics.** No generic
  repository layer, no second ORM or query builder (ADR-0003).
- **BullMQ on Redis** for work that is slow, scheduled, retry-worthy or debounced. Ordinary CRUD,
  reads and what-if simulations stay synchronous (ADR-0004).
- **Domain mathematics lives in `packages/finance-math`** as pure functions; services orchestrate.
- The out-of-scope list in `01-product-and-feature-analysis.md §3` — microservices, Kafka,
  Kubernetes, CQRS, event sourcing, GraphQL, ML models, bank integrations, tags, multi-currency —
  is a firewall, not a backlog.

## The git history is diploma evidence

The university reviews this repository as evidence that the system was developed gradually and
honestly. `docs/00-planning/06-git-and-commit-strategy.md` has the detail; what follows always
applies.

### Never manufacture activity

- No empty commits, no backdating, no `--author` or `user.name` / `user.email` overrides.
- No cosmetic edits made only to produce a commit.
- No deliberately introduced bugs followed by a "fix".
- No rewriting of history to change how the activity looks.
- No AI, Claude, Cursor, "generated by" or co-author references in commits, branches or pull
  requests. Agent tooling appends a `Co-authored-by:` trailer on its own, so check after every
  commit with `git log -1 --format=%B | rg -i 'co-authored|cursor|claude|generated'` and rebuild
  the commit without it if one appears. Rebuilding an unpublished commit this way is allowed; it
  changes only the message, never the author, the date or the content.

### Commits

- Conventional Commits with a module scope: `feat(ledger): create transfers as paired rows`.
  Scopes are listed in `06-git-and-commit-strategy.md §2`.
- Never `update`, `fix`, `changes`, `wip`, `final`.
- One commit is one coherent milestone that leaves the repository working.
- Tests travel with the code they verify, unless adding a test suite is itself the milestone.
- There is no commit quota. A small task may need one commit or five. Never split atomic work to
  raise the count, and never combine unrelated work to lower it.
- Stage files explicitly. Never `git add -A` or `git add .`.
- **Never push, merge or open a pull request without explicit approval.**

## How a task is done

1. Read the relevant documents and inspect the existing implementation.
2. Keep the scope small. One task at a time.
3. Propose the commit plan before editing.
4. Implement incrementally. Before every commit, all of these must pass:
   `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
5. Verify runtime behaviour yourself — start the services and call them — rather than asking for
   manual confirmation.
6. Report what changed, how it was verified, and the commits that were created.

Do not implement future chapters early. Do not do unrelated "helpful" work; note it as a possible
future task instead.

## Leave alone unless the task is about them

- `.github/workflows/ci.yml` runs the same commands as local development. If a command changes,
  change both; never quietly weaken CI to make a run pass.
- `docs/00-planning/` is frozen. Corrections go into an ADR or a topic folder under `docs/`.
- An accepted ADR is never edited or renumbered. A changed decision gets a new ADR that
  supersedes it.

## Local environment

- The Docker CLI is often missing from the PATH: `/Applications/Docker.app/Contents/Resources/bin/docker`.
- Infrastructure uses host ports 5433 (PostgreSQL) and 6380 (Redis) to avoid clashing with local
  installations. Start it with `pnpm infra:up`, stop it with `pnpm infra:down`.
- Port 3000 is taken on the development machine, so the API defaults to 3100.
- pnpm 12 blocks install scripts; approve them explicitly in `pnpm-workspace.yaml` under `allowBuilds`.
- `apps/api` needs `unplugin-swc` under Vitest: esbuild drops the decorator metadata Nest DI relies on.
- `consistent-type-imports` is configured with decorator metadata for `apps/api`, so injected
  classes must stay value imports.
- `ConfigModule.forRoot()` validates the environment when the module file is imported, so e2e
  tests set the variables first and then `await import('../src/app.module')`.
