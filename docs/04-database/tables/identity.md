# Identity tables

## `users`

The identity table. Every user-owned table added later references `users.id`.

Introduced by migration `20261106063035_add_users` (Chapter 1, task 2). The fields come from
`docs/00-planning/03-technical-design.md` §1.1: `id, email (unique, citext), password_hash,
base_currency, timezone, created_at`.

### Columns

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `id` | `uuid` | no | `uuidv7()` | Generated by PostgreSQL 18, so ids are time-ordered whoever inserts the row. |
| `email` | `citext` | no | — | Unique regardless of case; stored as typed. |
| `password_hash` | `text` | no | — | A hash only. The algorithm is chosen with registration (task 3). |
| `base_currency` | `char(3)` | no | `'AMD'` | ISO 4217 code. v1 has a single currency (ADR-0002); the column keeps the schema ready for more. |
| `timezone` | `text` | no | — | IANA name such as `Asia/Yerevan`. Decides which month a transaction belongs to. |
| `created_at` | `timestamptz(3)` | no | `CURRENT_TIMESTAMP` | Set by the database. |

Prisma maps these to the `User` model with camelCase fields (`passwordHash`, `baseCurrency`,
`createdAt`).

### Constraints

| Name | Rule | Why |
|---|---|---|
| `users_pkey` | primary key on `id` | |
| `users_email_key` | unique index on `email` | With `citext`, `Anna@Example.com` and `anna@example.com` collide. |
| `users_email_format_check` | `email ~ '^[^@[:space:]]+@[^@[:space:]]+$'` and at most 254 characters | Keeps out obviously broken values: no `@`, two `@`, whitespace, too long. 254 is the longest address SMTP accepts. Full validation belongs to the application. |
| `users_password_hash_not_empty_check` | `password_hash <> ''` | An empty hash would be a user nobody can authenticate as, or anyone can. |
| `users_base_currency_format_check` | `base_currency ~ '^[A-Z]{3}$'` | ISO 4217 shape. Which currencies are allowed is an application rule. |
| `users_timezone_not_empty_check` | `timezone <> ''` | PostgreSQL can't validate an IANA name in a `CHECK`, so the application does it. |

The migration also runs `CREATE EXTENSION IF NOT EXISTS citext`. Prisma maps `@db.Citext` to the
type but doesn't create the extension.

### Email: case-insensitive, not rewritten

The specification asks for `citext`. The database therefore decides "same address" without the
application lower-casing anything:

- uniqueness ignores case;
- lookups ignore case, so `findUnique({ where: { email } })` finds the user whatever casing is
  passed;
- the stored value keeps the user's own casing.

Trimming whitespace is left to the application at registration. The format check rejects
surrounding whitespace rather than silently removing it.

### Deliberately not included

- **`updated_at`:** not in the specification, and nothing updates a user yet. It gets added
  together with the first operation that changes a user.
- **Soft delete / `archived_at`:** the specification reserves soft delete for accounts and
  categories.
- **Roles, profile fields, email verification, sessions:** out of scope. Refresh tokens are
  their own table and arrive with authentication.

### Tests

`apps/api/test/users.schema.spec.ts` applies the migrations to a fresh PostgreSQL 18 container
and checks each rule as PostgreSQL enforces it. Violations are provoked with raw SQL and matched
on SQLSTATE (`23505` unique, `23514` check, `23502` not null) and on the constraint name.
